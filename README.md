# 39 donuts — Astro + JavaScript

Лендинг собирается в готовый HTML. JavaScript отвечает за меню, переключение форматов, FAQ, анкету и анимации. Исходники страницы написаны на Astro и JavaScript; React и TypeScript для них не используются.

## С чего начать

| Что нужно изменить                       | Где смотреть                                                     |
| ---------------------------------------- | ---------------------------------------------------------------- |
| Цвета, шрифты, общие скругления          | `src/styles/tokens.css`                                          |
| Внешний вид общей кнопки                 | `src/components/ui/button/button.css`                            |
| Текст или расположение конкретной кнопки | `.astro` и `.css` того блока, где она находится                  |
| Тексты и показатели секции               | `src/components/sections/<название>/content.js` и `.astro` рядом |
| Меню                                     | `src/components/layout/header/`                                  |
| Поля и шаги анкеты                       | `src/components/application/`                                    |
| Телефон, почта, соцсети и реквизиты      | `src/config/site.js`                                             |
| Изображения                              | `public/assets/`, пути в `src/config/assets.js` и данных секций  |
| SEO                                      | `src/config/seo.js`                                              |
| Порядок блоков на странице               | `src/pages/index.astro`                                          |

В [памятке по редактированию](docs/EDITING.md) есть карта всех блоков и примеры изменения цвета, кнопки и FAQ. [Устройство проекта](docs/ARCHITECTURE.md) объясняет связи между файлами.

## Запуск

Рекомендуется Node.js 22.23.0 из `.nvmrc`. Поддерживаются Node.js 22.13+ и 24+.

```sh
nvm use
npm ci
npm run dev -- --port 4321
```

Сайт откроется на `http://127.0.0.1:4321/`. Для просмотра готовой сборки:

```sh
npm run build:preview
npm run preview -- --port 4321
```

| Команда                      | Результат                                                                          |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| `npm run dev`                | Разработка; страницы содержат `noindex`                                            |
| `npm run format`             | Форматирование исходников через Prettier                                           |
| `npm run format:check`       | Проверка форматирования без изменения файлов                                       |
| `npm run lint`               | Проверка JavaScript через ESLint                                                   |
| `npm run test`               | Тесты анкеты и SEO                                                                 |
| `npm run build:preview`      | Сборка для сверки в `dist-preview/`, закрытая от индексации                        |
| `npm run preview`            | Локальный сервер для `dist-preview/`                                               |
| `npm run build`              | Production-сборка в `dist/` для `https://39donuts.ru/`                             |
| `npm run preview:production` | Локальный просмотр `dist/` после production-сборки                                 |
| `npm run check`              | Проверка форматирования, ESLint, тесты, production-сборка и проверки готового HTML |
| `npm run release`            | Все проверки и архив `releases/39donuts-production.tar.gz` с SHA256                |

`format:check` только проверяет стиль кода. Для исправления форматирования используется `format`. Для архивации командой `release` нужна утилита `tar`.

## Структура

```text
src/
├── pages/                     # Адреса страниц и порядок блоков главной
├── layouts/                   # Общий HTML-документ и метатеги
├── components/
│   ├── ui/                    # Кнопка, брендовый текст, иконки, изображения
│   ├── layout/                # Шапка, подвал, скроллбар
│   ├── sections/              # Девять блоков лендинга
│   │   └── formats/           # Разметка, CSS, данные и поведение блока рядом
│   └── application/           # Анкета: шаги, поля, переходы, проверка ответов
├── config/                    # Общие контакты, пути к ресурсам и SEO
├── content/                   # Текст политики
├── lib/                       # Общие функции SEO и вкладок
├── scripts/                   # Точка запуска JavaScript и общие анимации
└── styles/                    # Шрифты, переменные, базовые правила, импорт CSS
public/                        # Ресурсы, которые копируются в сборку без изменений
scripts/                       # Команды сборки, проверки HTML и упаковки
tests/                         # Тесты анкеты и SEO
deploy/                        # Пример правил Nginx
docs/                          # Редактирование, устройство, SEO и размещение
```

В папке каждой секции лежат её `.astro` и `.css`. Повторяющиеся тексты и показатели вынесены в `content.js`; у интерактивных секций есть `client.js`. Одноразовые заголовки и подписи остаются в разметке своей секции.

`tsconfig.json` нужен инструментам Astro для подсказок редактора; исходники остаются JavaScript. `dist/`, `dist-preview/` и `releases/` создаются командами сборки, не редактируются вручную и не включаются в Git.

## SEO и размещение

В хостинг загружается **содержимое** `dist/`, включая скрытый `.htaccess`. Это готовые HTML, CSS, JavaScript и ресурсы: Node.js для обслуживания сайта не нужен.

Production-сборка содержит метаданные, canonical, Open Graph, структурированные данные, `robots.txt`, `sitemap.xml`, политику по прежнему адресу и страницу 404. Предпросмотр содержит `noindex`; режим принудительно задаётся npm-командой.

Домен по умолчанию — `https://39donuts.ru/`. Для другого домена: `SITE_URL=https://example.ru npm run release`. Допустим только HTTPS-адрес без подпапки, параметров и якоря. Значение берётся из окружения команды, а не автоматически из `.env`. При смене домена отдельно обновляются серверные правила.

- [SEO-настройки](docs/SEO.md).
- [Подготовка выпуска и размещение](docs/DEPLOYMENT.md).
- [Результаты проверки](docs/AUDIT.md).
- [История переноса](docs/MIGRATION.md).

Редиректы HTTP/www, коды ответов и настройки официального домена проверяются после размещения. Локальный сервер не подтверждает настройки реального хостинга.

## Отправка заявок

Анкета пока завершает заполнение локально и не отправляет данные. Существующий обработчик Telegram будет подключён после получения исходников компании и проверки его контракта. Секреты обработчика не должны находиться в `public/` или браузерном JavaScript.

При загрузке файлов нужно сохранить действующий `/api/` и другие серверные файлы компании. Перед полноценным запуском необходимо проверить получение заявки в Telegram.
