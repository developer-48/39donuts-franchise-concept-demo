# 39 donuts — концепт сайта франшизы

Исходный код интерактивного концепта на React, TypeScript и Vite. Это самостоятельная демонстрация, не официальный сайт 39 donuts. Анкета не подключена к серверу: введённые данные остаются в памяти страницы и никуда не отправляются.

- [Открыть сайт](https://developer-48.github.io/39donuts-franchise-concept-demo/)
- [Посмотреть презентационный макет](https://developer-48.github.io/39donuts-franchise-concept-demo/showcase/)
- [Исходный код — ветка `source`](https://github.com/developer-48/39donuts-franchise-concept-demo/tree/source)
- [Опубликованная сборка — ветка `main`](https://github.com/developer-48/39donuts-franchise-concept-demo/tree/main)

GitHub Pages берёт файлы из корня `main`. Ветка `source` хранит исходники и не меняет сайт автоматически. Разделение сохраняет действующую публикацию и позволяет проверять изменения кода до сборки.

## Запуск и проверка

Нужны Node.js 20.19+ или 22.12+ и npm.

```bash
npm ci
npm run dev
npm run check
npm run build:pages
```

Vite выводит локальный адрес (обычно `http://127.0.0.1:5173/`). `npm run check` выполняет ESLint, Vitest, TypeScript и обычную Vite-сборку. `npm run build:pages` создаёт в `dist/` готовую для GitHub Pages сборку с правильным базовым путём, `404.html` для прямых переходов на внутренние маршруты и `.nojekyll`.
Изменения ветки `source` дополнительно проверяет GitHub Actions; публикация Pages выполняется отдельно.

## Выбранная версия

`/` и `/g` показывают утверждённый вариант **G**. Адреса `/e` и `/f` сохранены как контрольные версии для сравнения и регрессий; переключателя версий в интерфейсе нет. Контент, форматы, отзывы, FAQ и контакты берутся из одного модуля данных.

## Структура

```text
src/
  App.tsx                     маршруты и состав страницы
  components/                 переиспользуемые элементы и визуальные детали
  data/siteContent.ts         единый источник текста, чисел и адресов ассетов
  features/
    application/              анкеты E и F/G
    faq/                      категории вопросов и ответы
    formats/                  переключатель форматов и показатели
    navigation/               шапка, мобильное меню и desktop-скроллбар
  hooks/                      наблюдение за появлением секций
  sections/                   отдельные секции главной страницы
  styles/
    global.css                общая основа
    variant-e.css             сохранённая версия E
    variant-f.css             общие улучшения F/G
    variant-g.css             особенности и анимации G
    donut-scrollbar.css       desktop-скроллбар G
  types/Variant.ts            тип версий без связи с шапкой
public/
  assets/                     локальные иллюстрации, логотип, иконки
  showcase/                   опубликованный презентационный макет
  motion-preview/             сохранённая демонстрация анимаций
scripts/prepare-pages.mjs     подготовка Pages-сборки
docs/                         устройство проекта и результаты аудита
```

Порядок подключения CSS в `src/main.tsx` важен: G переопределяет F, F — E. Подробные границы модулей и правила внесения изменений описаны в [архитектуре](docs/ARCHITECTURE.md), результаты проверки — в [аудите](docs/AUDIT.md).

`dist/`, `node_modules/`, `work/`, `outputs/` и `.playwright-cli/` не входят в ветку с исходниками. `work/` и `outputs/` содержат локальные черновики, старые снимки и архивы; опубликованные макеты находятся в `public/showcase/`.

Значения оставлены в своих контекстах и закреплены контентными тестами. Источники изображений и ограничения на использование указаны в [ASSET_SOURCES.md](ASSET_SOURCES.md), сторонние лицензии — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
