# 39 donuts — Astro + JavaScript

Лендинг собирается в готовый HTML. JavaScript отвечает за меню, переключение форматов, FAQ, анкету и анимации. Исходники страницы написаны на Astro и JavaScript; React и TypeScript для них не используются.

## Локальная 3D-примерочная

Экспериментальная ветка `design/3d-motion-lab` находится в отдельном Git worktree `/Users/yusup/Documents/Codex/2026-10-17/39donuts-3d-lab`. Основа — утверждённый коммит `a0d19ca`. Эти варианты предназначены для локального выбора оформления.

```sh

```

Откройте `http://127.0.0.1:4324/lab/`. В левом нижнем углу находится панель «3D-примерочная».

| Адрес | Что отображается |
| --- | --- |
| `/lab/` и `/lab/formats/` | 3D только в блоке «Три формата кофейни» |
| `/lab/baseline/` | Исходный визуал без экспериментального 3D |

Панель позволяет сравнить исходный блок и утверждённую сцену форматов, остановить или повторить её анимацию. Остальные блоки используют исходные изображения и ранее согласованные анимации лендинга. Старые адреса `/lab/one/`, `/lab/two/`, `/lab/three/`, `/lab/all/` переводят на `/lab/formats/`; отвергнутые сцены и их модели удалены из текущего кода. Они доступны только в истории Git.

Код эксперимента находится в `src/experiments/three-d/`:

- `configuration.js` — состав готовых вариантов и обработка выбора;
- `Controls.astro`, `controls.js`, `controls.css` — панель сравнения;
- `client.js` — подключение выбранных сцен по мере приближения к экрану;
- `stage.js` — WebGL, камера, освещение, отрисовка по запросу и освобождение ресурсов;
- `architecture-renderer.js` — контактное затемнение GTAO и сглаживание для архитектуры;
- `static-meshes.js` — объединение совместимых неподвижных непрозрачных деталей без упрощения геометрии;
- `furniture.js` — локальная модель стула, её масштабирование и общие копии ресурсов в пределах одной сцены;
- `scenes.js`, `scenes.css` — композиции и анимации Three.js + GSAP;
- `models/` — модели трёх форматов кофеен, вспомогательная геометрия и резервные материалы.
- `studio.js`, `architecture-materials.js` — загрузка локального HDRI студии и фотографических карт материалов;
- `public/assets/three-d/` — HDRI и PBR-карты Poly Haven (CC0), происхождение в `ASSET_SOURCES.md`.

В экспериментальной версии оставлена только утверждённая сцена форматов. У трёх форматов разные конструкции: большой зал с цехом за стеклянной перегородкой и производственным оборудованием; компактная кофейня с L-образным баром без собственного цеха; закрытый квадратный уличный павильон с крышей, дверью и окном выдачи. Это концептуальные модели, не согласованные архитектурные планы. Архитектура использует реальную модель стула, фотографические карты поверхностей, отражающее стекло, окружение кафе Boma и GTAO. Светлые поверхности сохраняют исходный цвет отделки через шейдер, текстуры добавляют вариацию и рельеф. Подача остаётся архитектурным макетом, не фотографией готовой кофейни.

Все ресурсы запрашиваются с локального сервера; во время просмотра внешние сервисы не используются. Новая сцена форматов загружает около 12 МБ HDRI, модели и карт материалов по мере приближения к экрану. Это локальный эксперимент качества; перед публикацией выбранной комбинации нужно оптимизировать карты/модель и проверить реальные устройства. При недоступности карт и модели остаются процедурные материалы и мебель, при ошибке HDRI — нейтральное студийное окружение.

Сцены приостанавливаются вне экрана, при скрытии вкладки и открытии анкеты; настройка reduced motion сохраняет статичную композицию. При недоступности WebGL остаются исходные изображения. Основной маршрут `/` не подключает экспериментальные сцены, все `/lab/` закрыты от индексации.

## Оптимизация утверждённой 3D-сцены

Модели, их детализация, материалы, освещение, размеры холста, камеры и длительности анимаций сохранены. Оптимизация меняет способ подготовки и отрисовки сцены:

- Совместимые неподвижные непрозрачные детали объединяются в один Mesh с исходным материалом. Вершины, UV и нормали сохраняются; стекло, вывески, импортированная мебель и существующие InstancedMesh остаются отдельными. Объекты с дочерними объектами, нестандартной отрисовкой, отрицательным масштабом, displacement и object-space normal maps не объединяются.
- Карта теней рассчитывается при цветовом проходе. Проход нормалей GTAO не пересчитывает ту же карту теней второй раз; параметры теней и AO не понижены.
- Текстуры заранее передаются в GPU небольшими задачами с возвратом управления браузеру между ними. До завершения подготовки остаётся исходная фотография. Отмена подготовки и уничтожение сцены проверяются между загрузками.
- Форматы используют общие копии ресурсов одной сцены. Загруженные исходники сохраняются для повторного подключения; копии и временная геометрия освобождаются при уничтожении сцены.
- Изменение формата обновляет камеру, но не пересоздаёт холст и render targets при неизменных размерах.

18 JPEG-карт сохраняют исходные декодированные пиксели, разрешение и ICC. Оптимизация кодирования уменьшила их размер на 533 127 байт; прогрессивное JPEG-кодирование отклонено из-за более медленного декодирования в проверенном браузере. Суммарные ресурсы сцены занимают 11 500 134 байта до серверного сжатия. У 22 PNG лендинга и Open Graph повторно сжат только IDAT: исходные строки изображения и остальные PNG-чанки сохранены побайтно; экономия — ещё 266 905 байт.

В локальном сравнении исходной версии `98f778d` и оптимизированной сборки число команд отрисовки трёх форматов снизилось с 801/497/670 до 206/164/152 (на 67–77%). В трёх чередующихся запусках с отключённым HTTP-кешем медиана готовности сцены составила 2633 → 1700 мс, медиана самой длинной задачи до показа — 182 → 68 мс. Это замеры на тестовом Mac, а не обещание таких же результатов на телефонах. После загрузки обе версии работали плавно; уменьшение команд даёт запас производительности, а не подтверждает рост FPS во столько же раз.

Визуальная проверка охватила 27 статичных состояний в Chromium и WebKit на ширинах 320–1920 px и три точных кадра анимации. Видимых изменений не обнаружено; небольшие различия растеризации остались на границах 3D. Запасной вариант с фотографиями совпал попиксельно.

`tests/three-d-*.test.js` проверяют сохранение геометрии и атрибутов, исключения объединения, освобождение ресурсов, восстановление состояния AO и отмену подготовки текстур. Эти тесты входят в `npm run check`. При правках объединения или проходов рендеринга дополнительно нужно сравнивать все три модели на десктопе, мобильных ширинах и в движении. Для воспроизводимого сравнения в тестовом браузере фиксируется Math.random: GTAO использует случайный шум; рабочий код сайта его не меняет.

Настройки качества автоматически не понижаются при низком FPS. Реальные iPhone и Android нужно проверять отдельно: эмуляция размера экрана и сенсорного ввода не измеряет скорость их GPU. Порядок подготовки ресурсов основан на API [WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer), освобождение — на [руководстве Three.js](https://threejs.org/manual/pages/how-to-dispose-of-objects.html).

## Запуск

Рекомендуется Node.js 22.23.0 из `.nvmrc`. Поддерживаются Node.js 22.13+ и 24+.

```sh
nvm use
npm ci
npm run dev -- --port 4321
```

Сайт откроется на `http://127.0.0.1:4321/`. Для просмотра готовой сборки:

```sh
npm run build:preview
npm run preview -- --port 4321
```

| Команда                      | Результат                                                                          |
| ---------------------------- | ---------------------------------------------------------------------------------- |
| `npm run dev`                | Разработка; страницы содержат `noindex`                                            |
| `npm run format`             | Форматирование исходников через Prettier                                           |
| `npm run format:check`       | Проверка форматирования без изменения файлов                                       |
| `npm run lint`               | Проверка JavaScript через ESLint                                                   |
| `npm run test`               | Тесты анкеты и SEO                                                                 |
| `npm run build:preview`      | Сборка для сверки в `dist-preview/`, закрытая от индексации                        |
| `npm run preview`            | Локальный сервер для `dist-preview/`                                               |
| `npm run build`              | Production-сборка в `dist/` для `https://39donuts.ru/`                             |
| `npm run preview:production` | Локальный просмотр `dist/` после production-сборки                                 |
| `npm run check`              | Проверка форматирования, ESLint, тесты, production-сборка и проверки готового HTML |
| `npm run release`            | Все проверки и архив `releases/39donuts-production.tar.gz` с SHA256                |

`format:check` только проверяет стиль кода. Для исправления форматирования используется `format`. Для архивации командой `release` нужна утилита `tar`.

## Структура

```text
src/
├── pages/                     # Адреса страниц и порядок блоков главной
├── layouts/                   # Общий HTML-документ и метатеги
├── components/
│   ├── ui/                    # Кнопка, брендовый текст, иконки, изображения
│   ├── layout/                # Шапка, подвал, скроллбар
│   ├── sections/              # Девять блоков лендинга
│   │   └── formats/           # Разметка, CSS, данные и поведение блока рядом
│   └── application/           # Анкета: шаги, поля, переходы, проверка ответов
├── config/                    # Общие контакты, пути к ресурсам и SEO
├── content/                   # Текст политики
├── lib/                       # Общие функции SEO и вкладок
├── scripts/                   # Точка запуска JavaScript и общие анимации
└── styles/                    # Шрифты, переменные, базовые правила, импорт CSS
public/                        # Ресурсы, которые копируются в сборку без изменений
scripts/                       # Команды сборки, проверки HTML и упаковки
tests/                         # Тесты анкеты и SEO
deploy/                        # Пример правил Nginx
docs/                          # Редактирование, устройство, SEO и размещение
```

В папке каждой секции лежат её `.astro` и `.css`. Повторяющиеся тексты и показатели вынесены в `content.js`; у интерактивных секций есть `client.js`. Одноразовые заголовки и подписи остаются в разметке своей секции.

`tsconfig.json` нужен инструментам Astro для подсказок редактора; исходники остаются JavaScript. `dist/`, `dist-preview/` и `releases/` создаются командами сборки, не редактируются вручную и не включаются в Git.

## SEO и размещение

В хостинг загружается **содержимое** `dist/`, включая скрытый `.htaccess`. Это готовые HTML, CSS, JavaScript и ресурсы: Node.js для обслуживания сайта не нужен.

Production-сборка содержит метаданные, canonical, Open Graph, структурированные данные, `robots.txt`, `sitemap.xml`, политику по прежнему адресу и страницу 404. Предпросмотр содержит `noindex`; режим принудительно задаётся npm-командой.

Домен по умолчанию — `https://39donuts.ru/`. Для другого домена: `SITE_URL=https://example.ru npm run release`. Допустим только HTTPS-адрес без подпапки, параметров и якоря. Значение берётся из окружения команды, а не автоматически из `.env`. При смене домена отдельно обновляются серверные правила.

- [SEO-настройки](docs/SEO.md).
- [Подготовка выпуска и размещение](docs/DEPLOYMENT.md).
- [Результаты проверки](docs/AUDIT.md).
- [История переноса](docs/MIGRATION.md).

Редиректы HTTP/www, коды ответов и настройки официального домена проверяются после размещения. Локальный сервер не подтверждает настройки реального хостинга.
