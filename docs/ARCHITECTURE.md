# Устройство проекта

Структура следует назначению файлов в Astro: маршруты находятся в `src/pages/`, общий документ — в `src/layouts/`, компоненты — в `src/components/`, статические ресурсы — в `public/`. Внутри компонентов файлы сгруппированы по видимому блоку сайта.

## Как собирается страница

`src/pages/index.astro` задаёт порядок девяти секций, шапки, подвала и анкеты. `src/layouts/BaseLayout.astro` добавляет HTML-документ, метаданные, глобальные стили и точку входа JavaScript. Стили лендинга подключаются отдельно в `index.astro`, поэтому самостоятельные страницы политики и 404 не загружают CSS всех секций.

Astro формирует готовый HTML во время сборки. Тексты, показатели, все форматы и ответы FAQ присутствуют в нём до выполнения JavaScript. Клиентские модули управляют уже существующими элементами страницы.

## Где находится код блока

Например, папка `src/components/sections/formats/` содержит:

| Файл                   | Отвечает за                                       |
| ---------------------- | ------------------------------------------------- |
| `FormatsSection.astro` | Разметку секции и вывод карточек                  |
| `content.js`           | Названия форматов, изображения и показатели       |
| `formats.css`          | Внешний вид, состояния и адаптивные правила       |
| `client.js`            | Переключение форматов и обновление ARIA-состояний |

Так же устроены остальные секции. `client.js` есть только там, где требуется отдельное поведение. Подчасти, например галерея истории, преимущества сети и телефон в контактах, находятся внутри папки своей секции. Короткие одноразовые заголовки остаются в `.astro`; массивы карточек и повторяемые значения — в `content.js`.

Общие компоненты не привязаны к одной секции:

- `components/ui/` — кнопка, брендовый текст, SVG-иконки и изображения;
- `components/layout/` — шапка, подвал и основной скроллбар;
- `components/application/` — окно анкеты и его части.

Общие контакты и реквизиты находятся в `src/config/site.js`, пути к ресурсам — в `src/config/assets.js`, параметры SEO — в `src/config/seo.js`. Эти данные используются несколькими блоками и не дублируются в каждом из них.

## Анкета

`ApplicationWizardDialog.astro` собирает оболочку окна и его части. Папка `steps/` содержит разметку четырёх шагов, `fields/` — поля и группы переключателей. Плашки шагов, проверка ответов, результат и кнопки действий находятся в `progress/`, `review/`, `success/` и `actions/`: в каждой папке своя разметка и CSS.

| Файл               | Назначение                                                                   |
| ------------------ | ---------------------------------------------------------------------------- |
| `content.js`       | Названия шагов, варианты ответов и состав итогового просмотра                |
| `controller.js`    | Открытие и закрытие, переходы, фокус, блокировка фона и локальное завершение |
| `model.js`         | Правила проверки введённых значений                                          |
| `review/client.js` | Вывод заполненных ответов через DOM API и `textContent`                      |
| `application.css`  | Оболочка окна, основная сетка и адаптивные правила                           |

Все поля остаются в DOM при смене шага, поэтому ответы сохраняются. При новом открытии значения сбрасываются, как в утверждённой версии. Пустые необязательные ответы не показываются в итоговом просмотре; контакт не дублируется.

Будущая отправка подключается к серверному API после проверки действующего обработчика компании. Браузерные модули не должны содержать токены Telegram.

## Стили

Общие стили подключаются через `src/styles/global.css`, стили лендинга — через `src/styles/landing.css`. Оба файла содержат список импортов, а не набор исправлений разных секций в одном месте. Импорт `landing.css` в `src/pages/index.astro` расположен после импортов компонентов: это сохраняет порядок базовых правил и стилей секций.

Порядок подключения:

1. `fonts.css` подключает шрифты.
2. `tokens.css` задаёт палитру, шрифтовые переменные, ширину контейнера, отступы и скругления.
3. `base.css` содержит сброс, фокус, скрытые элементы и базовые правила документа.
4. `layout.css` задаёт общий контейнер, секции и заголовки.
5. Общие стили кнопки и брендового текста подключаются в `global.css`.
6. `landing.css` подключает глобальные стили, CSS шапки, секций, анкеты, подвала и скроллбара; затем — `motion.css` для общих состояний анимаций.

Стили компонентов используют обычные CSS-селекторы. Их порядок подключения явный: перенос правила между файлами или изменение порядка импортов может изменить приоритет. Для правки одного блока сначала открывайте его CSS, а не добавляйте новое переопределение в конце общего файла.

Главная страница находится в `.site`. Этот класс задаёт светлую тему лендинга и сохраняет отличия от самостоятельных страниц политики и 404. Общая палитра находится в `tokens.css`; цвета логотипа и иллюстраций остаются частью самих SVG/изображений.

## JavaScript

`src/scripts/main.js` запускает модули интерфейса. Меню находится в `components/layout/header/client.js`, скроллбар — в `components/layout/scrollbar/client.js`, форматы и FAQ — в `client.js` своих секций, анкета — в её `controller.js`.

`src/lib/tabs.js` содержит общую механику вкладок и клавиатуры. `src/scripts/motion.js` управляет анимациями через IntersectionObserver и учитывает reduced motion. Скроллбар с пончиками работает на широких экранах с точным указателем; на мобильных остаётся обычный скролл.

## Сборка и качество кода

Версия Node указана в `.nvmrc`, зависимости зафиксированы в `package-lock.json`. Prettier с плагином Astro отвечает за форматирование, ESLint — за JavaScript. Для VS Code в `.vscode/` есть рекомендуемые расширения Astro/Prettier и настройка форматирования при сохранении; стиль отступов также задан в `.editorconfig`. `npm run check` объединяет проверку форматирования, линтер, тесты, production-сборку и проверки готового HTML/SEO. Результаты фактической приёмки записываются отдельно в [AUDIT.md](AUDIT.md).

`npm run build` выпускает `dist/`; `npm run build:preview` — `dist-preview/` с `noindex`. В хостинг передаётся готовая production-сборка, исходники и инструменты разработки остаются в репозитории. Подробности — в [DEPLOYMENT.md](DEPLOYMENT.md).

## Добавление нового блока

Создайте папку в `src/components/sections/` с `.astro` и `.css`. При необходимости добавьте `content.js` и `client.js`. Подключите компонент в `src/pages/index.astro`, его CSS — в `src/styles/landing.css`, а инициализацию поведения — в `src/scripts/main.js`. Если нужен пункт меню, добавьте его в `components/layout/header/content.js`.

Новая секция главной не является отдельным URL и не добавляется в sitemap. Для отдельной страницы нужен файл в `src/pages/`, собственные метаданные и решение о её индексации.
