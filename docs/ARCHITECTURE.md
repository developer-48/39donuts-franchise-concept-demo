# Архитектура и границы модулей

Актуальное состояние после аудита 22 октября 2026. Пользовательская инструкция — [PROJECT_GUIDE.md](PROJECT_GUIDE.md), карта 3D — [3D.md](3D.md).

## 1. Ответственность верхних папок

| Папка                         | Ответственность                                           | Не её задача                                   |
| ----------------------------- | --------------------------------------------------------- | ---------------------------------------------- |
| `src/pages/`                  | URL, параметры конкретной страницы, статические endpoints | Переиспользуемые блоки и общая композиция      |
| `src/layouts/`                | HTML-документ, метаданные, общие подключения              | Данные конкретной карточки                     |
| `src/components/landing/`     | Порядок секций и состав лендинга                          | Маршрутизация и отрисовка WebGL                |
| `src/components/sections/`    | Содержание, разметка, CSS и поведение своего блока        | Общие реквизиты и код соседнего блока          |
| `src/components/layout/`      | Шапка, подвал, scrollbar                                  | SEO-URL и геометрия 3D                         |
| `src/components/ui/`          | Общие примитивы интерфейса                                | Управление всей анкетой или страницей          |
| `src/components/application/` | Полный сценарий анкеты                                    | Секреты Telegram и серверная обработка         |
| `src/experiments/three-d/`    | Дополнительный 3D-вид форматов и его жизненный цикл       | Основное HTML-содержание или бизнес-показатели |
| `src/config/`                 | Общие контакты, пути и SEO-настройки                      | Состояние открытого окна                       |
| `src/lib/`                    | Небольшие общие функции вкладок и SEO                     | Всё, для чего не нашлась папка                 |
| `public/`                     | Локальные ресурсы для прямого копирования                 | Исходники клиентской логики и отчёты проверки  |
| `scripts/`                    | Инструменты Node для сборки и проверки                    | Код, который должен исполняться в браузере     |

Это композиция статического сайта по видимым секциям. Дополнительные слои приложения или универсальный UI-конструктор здесь не нужны.

## 2. Направление зависимостей

```text
pages → LandingPage → BaseLayout + компоненты секций
                         ↓                 ↓
                    config / lib      UI + content.js

main.js → контроллеры интерфейса → локальные DOM-элементы

lab routes → Controls → 3D client → scenes → stage / модели / загрузчики
                             ↑
                  событие formats:change
```

Переиспользуемые компоненты не импортируют файлы из `src/pages/`. Главная `/` не зависит от `experiments/`: она может работать без 3D. `tests/structure.test.js` проверяет эти границы, относительные импорты и отсутствие циклов в текущем графе буквальных импортов. Итоговое разрешение модулей дополнительно проверяет сборщик.

`LandingPage.astro` используется и главной, и примерочной. Через именованный слот `experiment-controls` примерочная добавляет панель; через props — `noindex` и свой title. Другой копии HTML лендинга нет.

## 3. Разметка и данные

В секции соседствуют `.astro`, `content.js`, CSS и при необходимости `client.js`. Одиночные подписи остаются в разметке; массивы карточек и повторяемые значения вынесены в данные.

Контакты и адрес — в `config/site.js`. Пути общих ресурсов — в `config/assets.js`. Параметры домена и метаданных — в `config/seo.js`. FAQ использует одни и те же данные для HTML и JSON-LD. Политика — отдельный текст в `content/privacy.js`.

Финансовые показатели не рассчитываются из 3D-размеров и не синхронизируются автоматически между разными рекламными утверждениями.

## 4. CSS и каскад

- `global.css`: шрифты → токены → базовые правила → общий layout → UI.
- `landing.css`: global → шапка → секции в порядке страницы → анкета → scrollbar → общие анимации.
- `scenes.css` и `controls.css`: дополнительное оформление примерочной.

Каждый CSS-файл лежит рядом с владельцем. Общие импорты остаются явными; они не заменены набором импортов в случайном порядке из каждого компонента. Порядок загрузки имеет значение, поэтому стили лендинга импортируются в `LandingPage.astro` после импортов компонентов.

`.site` задаёт тему лендинга. Политика и 404 используют базовую тему. Селекторы глобальные; новые правила нужно проверять на пересечения с соседними блоками. Отдельный stylesheet рядом с компонентом не означает автоматического scoped CSS.

## 5. Браузерный код

`BaseLayout.astro` подключает `main.js` для интерактивного лендинга. Статические самостоятельные страницы передают `interactive={false}`. В текущем проекте нет клиентского роутера и повторной гидратации страниц.

`main.js` только запускает модули и связывает CTA с анкетой. Навигация, FAQ и форматы не хранят состояние друг друга. Статус анкеты передаётся событием, а не импортом её контроллера в scrollbar и 3D.

| Контракт                                          | Отправитель                  | Получатели                                        |
| ------------------------------------------------- | ---------------------------- | ------------------------------------------------- |
| `application:visibility`, `document`, `{ open }`  | `application/controller.js`  | `layout/scrollbar/client.js`, `three-d/client.js` |
| `formats:change`, `#formats`, `{ index }`         | `sections/formats/client.js` | `three-d/client.js`                               |
| `data-open-application`                           | Шаблоны CTA                  | `scripts/main.js`                                 |
| `data-step-body`, `data-wizard-step`, имена полей | Шаблоны анкеты               | `application/controller.js`, `model.js`           |

Имя события форматов экспортируется из `sections/formats/events.js`. Его получает подписчик после обновления активной вкладки, текста, изображения и ARIA. Начальное выбранное значение 3D также считывает при подключении, поэтому выбор во время загрузки не теряется.

## 6. Анкета

Контроллер оркестрирует открытие, шаги, фокус и локальное завершение; `model.js` содержит чистые правила. Обзор строится DOM API с `textContent`, а не вставкой введённого пользователем HTML. Поля всех шагов остаются в DOM; обзор исключает пустые ответы и повтор контакта.

Шаги, поля, плашки, действия и результат разделены на небольшие шаблоны. Сам контроллер остаётся одним связным сценарием, а не набором файлов по одной функции. Сетевой слой ещё не реализован: его контракт зависит от обработчика компании.

## 7. 3D

Общий модуль отделён от секции с бизнес-данными. `client.js` монтирует сцену, `scenes.js` задаёт композицию/анимации, `stage.js` владеет renderer/камерой/ресурсами, `architecture-renderer.js` — проходами изображения.

`models/cafe/` содержит три планировки и общие элементы. Материалы, стены, оборудование и посадка разделены по назначению. Повторяемые элементы используются функциями, а не копиями геометрии в каждом файле. Объединение статичных Mesh — отдельная оптимизация после построения; исходные планы от него не зависят.

Автоматические тесты проверяют загрузку текстур, отмену, отдельные проходы рендера и освобождение геометрии. Полный сценарий включения, отключения и повторного подключения дополнительно проверяется в браузере. 3D не является единственным носителем текста: фотографии остаются запасным вариантом, характеристики — в HTML.

## 8. Инструменты и документация

`npm run check` проверяет код, текущую структуру, production HTML/SEO и ссылки документации. `check:preview` проверяет отдельный SEO-режим демонстрации. CI выполняет обе команды на push/PR и использует Node из `.nvmrc`; это проверки, а не публикация.

`verify-docs.mjs` проверяет существование локальных файлов и папок в Markdown-ссылках README и `docs/`. Он не доказывает актуальность текста и не обращается к внешним сайтам. Описание меняется вместе с кодом, а исторические проверки остаются в датированных разделах `AUDIT.md`.

Назначение `src/pages/`, `public/` и layout соответствует [структуре Astro](https://docs.astro.build/en/basics/project-structure/). Поведение обработанных скриптов описано в [руководстве Astro](https://docs.astro.build/en/guides/client-side-scripts/).
