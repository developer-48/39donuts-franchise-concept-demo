# Устройство проекта

## Маршруты и композиция

`src/App.tsx` выбирает вариант по относительному пути Vite `BASE_URL`: корень ведёт на G, а `/e`, `/f`, `/g` доступны напрямую. Каждая версия использует одинаковый порядок девяти секций и общие данные из `src/data/siteContent.ts`. Вариант E оставлен как исторический контроль; F — промежуточная итерация; G — текущая выбранная версия.

Секции из `src/sections/` отвечают за разметку крупных блоков страницы. Интерактивные подсистемы находятся в `src/features/`: анкета, FAQ, форматы, навигация. Переиспользуемые визуальные элементы остаются в `src/components/`. Тип `Variant` вынесен в `src/types/Variant.ts`, чтобы другие модули не зависели от `Header` ради одного типа.

## Стили

`src/main.tsx` загружает слои строго в таком порядке:

1. `global.css` — токены, общие компоненты и адаптивная база;
2. `variant-e.css` — арт-дирекция исходной версии;
3. `variant-f.css` — изменения, общие для F и G;
4. `variant-g.css` — мобильные решения и анимации текущей версии;
5. `donut-scrollbar.css` — отдельный desktop-скроллбар.

Классы `.site-e`, `.site-next`, `.site-f`, `.site-g` изолируют версии. Пока CSS сильно зависит от порядка правил; переносить селекторы между слоями следует вместе с визуальным сравнением E/F/G на desktop и mobile. При разделении прежнего `variant-next.css` текст правил не менялся: он разрезан на границе начала блока G, а итоговый CSS-бандл остался побайтно тем же.

## Данные и ассеты

`siteContent.ts` — единый перечень текстов, цифр, контактов и путей к изображениям. `public/assets/official/` хранит локальные копии изображений исходного сайта; `public/assets/concept/` — специально созданные элементы концепта; `public/assets/icons/` — SVG-пиктограммы. Имена оригинальных файлов сохранены, а понятные алиасы даны в объекте `assets`. Сведения о происхождении — в корневом `ASSET_SOURCES.md`.

`public/showcase/` и `public/motion-preview/` являются самостоятельными статическими страницами. Их адреса не должны измениться при реорганизации кода. Они автоматически копируются Vite в `dist/`.

## Сборка и публикация

Ветка `source` хранит код, документацию и статические исходные ресурсы. Ветка `main` содержит только содержимое `dist/`, откуда GitHub Pages публикует сайт. Публикация вручную: выполнить `npm ci`, `npm run check`, `npm run build:pages`, проверить готовую сборку, затем перенести содержимое `dist/` в `main` отдельным коммитом. Нельзя синхронизировать непроверенную локальную папку проекта целиком с `main`.

`prepare-pages.mjs` создаёт `404.html` как копию `index.html`, чтобы прямые переходы на `/e`, `/f` и `/g` корректно работали на GitHub Pages. Базовый путь задаётся в `build:pages`.

## Анкета

E сохраняет одноэкранную форму, F/G используют четырёхшаговый мастер. Состояние хранится в React, без `fetch`, XHR, local/session storage и серверного `action`. Надпись «Отправить заявку» в G завершает локальный сценарий; серверного приёма заявок в концепте нет. Для реального сайта это отдельная задача с API, обработкой ошибок и юридической проверкой.
