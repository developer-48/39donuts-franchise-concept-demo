Документ описывает реализацию после аудита 22 октября 2026. Его цель — показать, как читать проект и менять его без поиска по несвязанным большим файлам. Для знакомства достаточно читать разделы по порядку; для конкретной правки используйте таблицы.

## 2. Какой подход использован

**Astro + JavaScript, статическая генерация HTML.**

1. `.astro`-компоненты описывают разметку.
2. Обычные `.js`-файлы хранят данные и поведение.
3. CSS задаёт оформление и адаптивность.
4. При сборке Astro создаёт готовые HTML-страницы и собирает необходимые CSS/JS через Vite.
5. Браузер получает текст страницы сразу в HTML; JavaScript добавляет переключения, меню, анкету и анимации.

Здесь нет React-приложения, гидратации React-компонентов или сервера Next.js. `div id="root"` в общем документе — обычный HTML-контейнер; его имя не означает, что страница рендерится React.

Vite не нужно отдельно настраивать вместо Gulp: в этом проекте он является внутренним инструментом Astro. На хостинг передаются готовые файлы. Для обслуживания самой статической страницы Node.js не требуется; обработчик заявок является отдельной серверной задачей.

Файлы сгруппированы **по блокам сайта**. Например, данные, HTML, стили и переключение форматов лежат рядом в одной папке. Общие элементы используются повторно, а 3D вынесено в отдельный модуль. Для этого лендинга такая организация проще, чем дополнительные слои приложения, глобальное хранилище состояния или система микросервисов.

Подход соответствует назначению папок в [структуре Astro](https://docs.astro.build/en/basics/project-structure/) и модели [Astro-компонентов](https://docs.astro.build/basics/astro-components/). Группировка по секциям — наше решение для удобства сопровождения, а не обязательное требование фреймворка.

## 3. Запуск и сборка

В корне проекта:

```sh
nvm use
npm ci
npm run dev -- --port 4324
```

`nvm use` выбирает Node из `.nvmrc`; без nvm установите указанную там версию обычным способом. `npm ci` устанавливает зависимости строго по `package-lock.json`. Повторять установку после каждой текстовой правки не нужно.

Откройте один из адресов:

| URL                      | Что показывает                           |
| ------------------------ | ---------------------------------------- |
| `/`                      | Лендинг с фотографиями                   |
| `/lab/formats/#formats`  | Утверждённую 3D-модель в блоке форматов  |
| `/lab/baseline/#formats` | Тот же блок с фотографиями для сравнения |
| `/lab/`                  | Вход в 3D-примерочную                    |
| `/privacy-policy/`       | Политику обработки данных                |

Базовый локальный адрес — `http://127.0.0.1:4324`. Если порт занят, завершите свой старый сервер либо задайте другой свободный порт. Остановка сервера в его терминале — `Ctrl+C`.

Режимы различаются назначением:

| Команда                      | Режим и папка                                               |
| ---------------------------- | ----------------------------------------------------------- |
| `npm run dev`                | Разработка, страницы с `noindex`, без готовой папки выпуска |
| `npm run build:preview`      | Демонстрационная сборка в `dist-preview/`, `noindex`        |
| `npm run build`              | Production-сборка в `dist/`                                 |
| `npm run preview`            | Просмотр уже существующей `dist-preview/`                   |
| `npm run preview:production` | Просмотр уже существующей `dist/`                           |

`preview` не пересобирает исходники. После их изменения сначала нужен соответствующий `build`. Режим выбирает [scripts/astro-command.mjs](../scripts/astro-command.mjs); `PUBLIC_SITE_MODE` в `.env` не переключает эти команды. Домен для метаданных задаётся отдельно через `SITE_URL` в окружении команды.

## 5. Как собирается страница

```text
src/pages/index.astro
  → components/landing/LandingPage.astro
      → layouts/BaseLayout.astro: <html>, <head>, метаданные, общие ресурсы
      → Header, девять секций, SiteFooter, ApplicationWizardDialog
      → styles/landing.css: порядок CSS всех блоков

src/pages/lab/index.astro или lab/[variant].astro
  → тот же LandingPage + Controls в именованном слоте
      → отложенная загрузка 3D только возле форматов
```

[pages/index.astro](../src/pages/index.astro) задаёт маршрут `/`, но не служит компонентом для других страниц. Порядок блоков находится в [LandingPage.astro](../src/components/landing/LandingPage.astro). [BaseLayout.astro](../src/layouts/BaseLayout.astro) отвечает за документ, title, description, canonical, Open Graph и JSON-LD.

В `.astro` код между `---` выполняется во время сборки. Текст и данные оттуда попадают в готовую разметку. Браузерный код подключается через обработанные Astro-теги `<script>` и обычные модули. Общая точка запуска интерфейса — [src/scripts/main.js](../src/scripts/main.js).

В коде нет клиентского роутера Astro: переход на другую страницу загружает новый документ. Модули интерфейса инициализируются один раз для этого документа. При добавлении самостоятельной страницы с `BaseLayout` используйте `interactive={false}`, если она не содержит интерфейс лендинга; так политика и 404 не запускают его меню/анкету/scrollbar.

## 7. Как изменить текст или показатель

Для изменения инвестиций откройте [formats/content.js](../src/components/sections/formats/content.js). У нужного формата найдите элемент `facts` по `label` и измените его `value`.

```js
{ label: 'Инвестиции', value: 'от 7 000 000 ₽' }
```

Разметку карточки при замене одного значения трогать не нужно. Если меняется длина текста, проверьте переносы на телефоне. Числа в первом экране, выручке, карточке истории и форматах являются отдельными утверждениями; они не рассчитываются автоматически друг из друга.

Для FAQ правятся `question` и `answer` в [faq/content.js](../src/components/sections/faq/content.js). Эти же данные участвуют в SEO-разметке FAQ. Для названия кнопки откройте `.astro` владельца кнопки — например шапки или первого экрана.

Контакты, телефон, соцсети, часы работы и реквизиты задаются в [config/site.js](../src/config/site.js). Адрес подвала и JSON-LD берут одну запись `postalAddress`. Политика хранится отдельно в [content/privacy.js](../src/content/privacy.js): её текст также нужно сверять при изменении обработки данных.

## 8. Как изменить цвет, шрифт и кнопку

Общая палитра находится в [styles/tokens.css](../src/styles/tokens.css):

```css
--purple: #7a44ca;
--purple-hover: #6334ad;
--orange: #fe7f16;
--green: #7db234;
```

Там же заданы `--font-body`, `--font-heading`, `--font-brand`, `--container`, `--radius`, `--radius-lg`, `--section-space`. Подключение шрифтов — в [fonts.css](../src/styles/fonts.css): Manrope для текста, Unbounded для заголовков, Nunito для брендовых надписей.

Правка `--purple` не перекрашивает SVG-логотип, фотографии или 3D-материалы. Их цвета задаются самими ресурсами либо материалами сцены. `BrandText.astro` выводит `39 donuts` и `39 м²` в согласованном текстовом начертании; это отличается от готового SVG-логотипа в шапке.

Общая кнопка — [Button.astro](../src/components/ui/button/Button.astro), её стили — [button.css](../src/components/ui/button/button.css). При наличии `href` компонент выводит ссылку, иначе кнопку. Переданные атрибуты сохраняются.

```astro
<Button type="button" data-open-application>
  Стать партнёром
</Button>
```

`data-open-application` запускает анкету. Общие отступы кнопок меняются в `button.css`; размещение и специальные размеры кнопки конкретного блока — в CSS этого блока. Не нужно менять все кнопки ради одного элемента шапки.

Иконки выбираются через [Icon.astro](../src/components/ui/icon/Icon.astro). Они состоят из локальных SVG или встроенных SVG-путей; новый рисунок должен быть добавлен туда и использоваться по `name`.

## 9. Почему CSS подключается именно так

[global.css](../src/styles/global.css) и [landing.css](../src/styles/landing.css) — явные списки импортов. Первый содержит шрифты, токены, базовые правила, общий layout и UI. Второй подключает их и затем стили компонентов в порядке страницы, а в конце — общие правила анимаций.

Стили используются глобально, а не изолируются автоматически через локальные `<style>`-блоки Astro. Это сознательный выбор, сохраняющий согласованный каскад. Изменение порядка импортов может изменить результат даже при тех же объявлениях.

Рабочий порядок: общий параметр → `tokens.css`; правило секции → её `.css`; единичная адаптивная правка → существующий media query этой секции. Новое переопределение в конце общего файла затруднит понимание владельца правила.

Подключение и границы CSS дополнительно описаны в [ARCHITECTURE.md](ARCHITECTURE.md). Сам факт поддержки Astro scoped styles не требует переписывать проверенную тему — это отдельный вариант организации, описанный в [официальном руководстве](https://docs.astro.build/en/guides/styling/).

### Обычные анимации и scrollbar

[scripts/motion.js](../src/scripts/motion.js) следит за появлением `.reveal`, `.motion-item` и `.motion-trigger` через IntersectionObserver. Он один раз добавляет `is-visible` и прекращает наблюдение за показанным элементом. Общие переходы находятся в [styles/motion.css](../src/styles/motion.css), а специальные движения цифр, пончика и линии шагов — в CSS соответствующей секции. При `prefers-reduced-motion` элементы сразу показываются без этого движения. Анимации 3D описаны отдельно в разделе 13.

Основной пончиковый scrollbar находится в [layout/scrollbar/](../src/components/layout/scrollbar/): `.astro` задаёт разметку, `client.js` — позицию, перетаскивание и клавиатуру, `scrollbar.css` — рельс и изображение. Он включается при ширине от 901 px, точном указателе и выключенном forced colors; на телефоне сохраняется обычная прокрутка. Высота бегунка `thumbHeight` в JS и `height` в CSS должна совпадать. Прокрутка внутри анкеты оформлена в её CSS и не использует пончиковый бегунок.

## 10. Как заменить картинку

1. Добавьте файл в `public/assets/images/<секция>/`.
2. Обновите путь в [config/assets.js](../src/config/assets.js) либо в `content.js` секции.
3. Проверьте `alt`: декоративная картинка имеет пустое описание, содержательная — соответствующее изображению.
4. При новом пути или размерах обновите [imageMetadata.json](../src/components/ui/image/imageMetadata.json).
5. Проверьте `object-fit`, высоту и положение в CSS секции на телефоне и компьютере.

`SiteImage.astro` подставляет ширину и высоту из метаданных, чтобы браузер заранее выделял место. По умолчанию используется `loading="lazy"` и `decoding="async"`; основные картинки первого экрана загружаются раньше.

Все файлы из `public/` копируются в сборку напрямую. Они не получают автоматическую обработку или новые размеры только от наличия в этой папке. Локальные изображения не зависят от доступности исходного сайта. Лицензии и происхождение ресурсов зафиксированы в [ASSET_SOURCES.md](../ASSET_SOURCES.md) и [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md).

## 11. Как устроена анкета

[ApplicationWizardDialog.astro](../src/components/application/ApplicationWizardDialog.astro) собирает четыре шага:

| Шаг     | Разметка                  | Поля                                    |
| ------- | ------------------------- | --------------------------------------- |
| О вас   | `steps/AboutStep.astro`   | `fullName`, `age`, `experience`, `role` |
| Проект  | `steps/ProjectStep.astro` | `format`, `investment`, `region`        |
| План    | `steps/PlanStep.astro`    | `marketing`, `reason`, `about`          |
| Контакт | `steps/ContactStep.astro` | `contact` и обзор предыдущих ответов    |

Все пути этой таблицы относятся к `src/components/application/`.

- `content.js` хранит заголовки, варианты radio и состав обзора.
- `model.js` читает ответы, проверяет значения и исключает пустые поля из обзора. Его чистые функции проверяются без браузера.
- `controller.js` управляет открытием, шагами, ошибками, фокусом, блокировкой фона и локальным завершением.
- `fields/` содержит общую разметку полей и их CSS.
- `progress/`, `review/`, `actions/`, `success/` отвечают за плашки, итоговый обзор, кнопки и экран результата.
- `application.css` задаёт оболочку и стабильные размеры окна; длинное содержимое прокручивается внутри.

Назад можно возвращаться без потери введённого. Переход вперёд проверяет обязательные ответы. Обзор показывает все заполненные поля первых трёх шагов; контакт не дублируется, поскольку находится над ним. При новом открытии анкета сбрасывается.

**Текущая кнопка «Отправить заявку» выполняет локальное завершение. Сетевой отправки нет.** Нет API-запроса, Telegram-токена, CRM или сохранения ответов на сервере. Экран «Анкета готова» сам по себе не подтверждает получение заявки компанией.

Для подключения реальной отправки нужно получить и проверить старый серверный обработчик: URL, метод, поля, ошибки, защиту и формат ответа. Клиент передаёт данные этому обработчику, а сервер работает с Telegram. Секреты бота не должны попадать в статический JavaScript. Такой контракт сейчас не предоставлен; придумывать его в документации нельзя.

### Добавить поле

1. Добавьте компонент поля с уникальным `name` в `steps/`.
2. Добавьте имя в `fieldNames` в `model.js`, чтобы оно читалось из формы.
3. При необходимости добавьте правило в `validateStep()`.
4. Добавьте поле в `reviewDefinitions` в `content.js`, если оно должно показываться в обзоре.
5. Проверьте `wide` для длинного текста и обновите тесты обязательности/обзора.
6. После подключения API также обновите серверный контракт; одной разметки недостаточно.

Анкета реализована именно как четыре согласованных шага, а не универсальный конструктор. Добавление пятого шага требует согласовать шаблон, контроллер, прогресс, правила проверки и обзор.

## 12. Как связаны модули интерфейса

[main.js](../src/scripts/main.js) запускает навигацию, форматы, FAQ, появление элементов, scrollbar и анкету. Он связывает кнопки `data-open-application` с `application.open()`.

Два события позволяют модулям взаимодействовать без прямых вызовов друг друга:

| Событие                                | Кто отправляет                               | Кто слушает    | Данные                 |
| -------------------------------------- | -------------------------------------------- | -------------- | ---------------------- |
| `application:visibility` на `document` | Контроллер анкеты                            | Scrollbar и 3D | `{ open: true/false }` |
| `formats:change` на `#formats`         | Переключатель форматов после обновления HTML | 3D-модуль      | `{ index: 0/1/2 }`     |

Имя второго события находится в [formats/events.js](../src/components/sections/formats/events.js). Оно не всплывает: подписка делается на саму секцию. 3D больше не определяет изменение формата по отдельным событиям мыши и клавиатуры.

`data-*`, `id` и ARIA-связи в шаблонах — часть контракта с JavaScript. Переименование `data-format-index` или `data-step-body` требует согласованной правки контроллера и проверки поведения.

Основной `/` использует фотографии. Согласование 3D в примерочной и включение этого оформления в будущую главную — отдельные действия. Простая замена ссылки не переносит обработчик заявок и не публикует сайт.

## 14. SEO и новые страницы

Готовый HTML содержит заголовки, тексты, все карточки форматов и FAQ. Метаданные формируются в [BaseLayout.astro](../src/layouts/BaseLayout.astro), настройки — в [config/seo.js](../src/config/seo.js), функции — в [lib/seo.js](../src/lib/seo.js).

Подготовлены title/description, canonical, Open Graph, JSON-LD, robots.txt, sitemap и страница 404. Индексируемые пути перечислены в `indexablePaths`. Секции с якорями не являются отдельными страницами и в sitemap не перечисляются.

Для новой страницы создайте файл в `src/pages/`, используйте `BaseLayout`, задайте заголовок/описание и решите, нужно ли её индексировать. Для индексируемой страницы добавьте путь в `indexablePaths` и проверьте canonical. Вспомогательные компоненты кладутся вне `pages/`, чтобы не превращать их в маршруты.

Домен по умолчанию — `https://39donuts.ru/`. Переопределение для сборки:

```sh
SITE_URL=https://example.ru npm run build
```

Поддерживается HTTPS origin без подпапки, query и якоря. Настройки серверных редиректов при смене домена меняются отдельно. `.env.example` документирует эти ограничения, но `SITE_URL` читается конфигурацией из окружения команды.

Техническая SEO-подготовка не является обещанием позиций в поиске. После публикации отдельно проверяются домен, HTTP-коды, индексация и доступы к сервисам поисковиков. Подробности — в [SEO.md](SEO.md).

## 15. Как безопасно добавить блок

1. Создайте `src/components/sections/<имя>/`.
2. Добавьте `.astro`, CSS, при необходимости `content.js` и `client.js`.
3. Импортируйте компонент в `LandingPage.astro` и поставьте его на нужное место.
4. Подключите CSS в `styles/landing.css` с учётом каскада.
5. Если нужен JavaScript, экспортируйте функцию инициализации и подключите её через `main.js`; не запускайте тот же модуль ещё раз из шаблона.
6. Добавьте уникальные `id`, правильную иерархию заголовков и подписи для интерактивных элементов.
7. При ссылке из меню обновите `layout/header/content.js`.
8. Проверьте готовый HTML, узкие экраны, клавиатуру, reduced motion и соседние блоки.

При удалении блока также убираются его импорт CSS, инициализация поведения, ссылки меню и ставшие ненужными ресурсы. Не нужно переносить файлы в общие `utils/`, если ими владеет только одна секция.

Если меняется утверждённый состав секций или значимые тексты, обновите соответствующие ожидания в `scripts/verify-static-build.mjs`. Проверка хранит контракт текущего лендинга; удаление нужного раздела не должно случайно пройти как обычная техническая правка.

## 16. Проверка, выпуск и передача

Повседневный цикл:

```sh
npm run format
npm run check
npm run check:preview
```

`check` включает линтер, тесты, сборку, HTML/ARIA/SEO и проверку локальных ссылок документации. `tests/structure.test.js` также проверяет относительные импорты, отсутствие циклов, запрет импорта маршрутов из переиспользуемых модулей и отсутствие зависимости главной от экспериментального 3D.

Автоматические тесты не сравнивают внешний вид. После правки CSS, разметки, шрифта, картинки, материала или камеры нужна браузерная сверка с утверждённым результатом. Порядок и минимальные сценарии приведены в [TESTING.md](TESTING.md).

Для готового архива:

```sh
npm run release
```

Архив `releases/39donuts-production.tar.gz` содержит файлы из `dist/`, включая `.htaccess`; рядом находится SHA256. Сейчас полный `dist/` также содержит закрытые от индексации `/lab/` и их ресурсы. Наличие production-архива не означает, что 3D уже включено на `/` или подключён Telegram.

На хостинг загружается содержимое сборки. Старый `/api/`, серверные секреты и настройки компании сохраняются. Инструкция по размещению — [DEPLOYMENT.md](DEPLOYMENT.md). Для передачи другому разработчику нужны исходники с lock-файлом и документацией; `node_modules/`, временные снимки и секреты для этого не требуются.

## 17. Почему некоторые файлы больше других

Размер сам по себе не определяет качество. `controller.js` анкеты объединяет связанные переходы и фокус, `stage.js` — жизненный цикл одной WebGL-сцены. Делить каждую небольшую функцию в отдельную папку затруднило бы чтение.

Деление оправдано, когда файл обслуживает разные самостоятельные задачи. Поэтому общий лендинг вынесен из маршрута в `LandingPage.astro`, а бывший файл трёх 3D-моделей разделён на три планировки и общие детали. Новые файлы имеют понятных владельцев; одинаковые элементы не копируются в каждый формат.

## 18. Если что-то не работает

| Симптом                                          | Что проверить                                                                                         |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| После правки ничего не изменилось                | Открыт ли нужный каталог/порт; при просмотре сборки выполнен ли новый `build`                         |
| `npm ci` или Astro не запускается                | Версия Node из `.nvmrc`, наличие lock-файла, текст ошибки установки                                   |
| Вижу фотографии вместо 3D                        | Открыт ли `/lab/formats/`, включён ли формат в панели, не указан ли `?scenes=none`, доступен ли WebGL |
| Фото видно некоторое время до модели             | 3D загружается возле блока; до окончания подготовки намеренно остаётся изображение                    |
| Изменил CSS-цвет, но логотип или 3D прежние      | SVG и материалы модели не используют автоматически токены интерфейса                                  |
| Новое поле не попало в обзор                     | `fieldNames`, `reviewDefinitions`, точное совпадение `name`                                           |
| «Отправить» не привело заявку в Telegram         | В этой версии пока нет серверного обработчика; это не ошибка настройки почты                          |
| Проверка документации упала после переноса файла | Обновите относительную ссылку на новый путь                                                           |
| Preview не индексируется                         | Это ожидаемый режим; официальный выпуск собирается командой `build`                                   |

Если вопрос остался, начните с [ARCHITECTURE.md](ARCHITECTURE.md) и найдите владельца соответствующего модуля. Результаты последнего аудита — в [AUDIT.md](AUDIT.md).
