## 2. Какой подход использован

**Astro + JavaScript + CSS, статическая сборка.** Компоненты собираются в готовый HTML заранее. JavaScript в браузере отвечает за меню, вкладки, анкету и анимации. На хостинг передаются готовые файлы; Node.js для отдачи страниц не нужен. Развёрнутое объяснение технологии — в [отдельном материале об Astro](meeting/ASTRO.md).

Код сгруппирован по блокам сайта: разметка, данные, стили и поведение секции находятся рядом. Общие элементы используются повторно.

## 3. Запуск

В терминале из корня проекта:

```sh
nvm use
npm ci
npm run dev -- --port 4324
```

Откройте `http://127.0.0.1:4324/`. Политика находится по адресу `/privacy-policy/`. Остановка сервера — `Ctrl+C`.

`nvm use` выбирает Node из [.nvmrc](../.nvmrc); без nvm установите эту версию другим способом. `npm ci` устанавливает зависимости по lock-файлу и не требуется после каждой текстовой правки.

| Команда                                     | Назначение                                                    |
| ------------------------------------------- | ------------------------------------------------------------- |
| `npm run dev -- --port 4324`                | Разработка с обновлением при правках                          |
| `npm run format`                            | Форматирование исходников и документации                      |
| `npm run check`                             | Формат, линтер, тесты, сборка, HTML/SEO и ссылки документации |
| `npm run check:preview`                     | Проверка демонстрационной сборки                              |
| `npm run build`                             | Production-файлы в `dist/`                                    |
| `npm run build:preview`                     | Демонстрация в `dist-preview/`, закрытая от индексации        |
| `npm run preview:production -- --port 4324` | Просмотр уже собранной `dist/`                                |
| `npm run preview -- --port 4324`            | Просмотр уже собранной `dist-preview/`                        |
| `npm run release`                           | Проверки и архив в `releases/`                                |

`preview` не пересобирает исходники: после изменений сначала выполните нужный `build`. Не запускайте два своих сервера на одном порту.

### Как собирается страница

`pages/index.astro → LandingPage.astro → BaseLayout + шапка + секции + подвал + анкета`.

Код между `---` в компоненте `.astro` выполняется при сборке. Браузерная точка входа — [src/scripts/main.js](../src/scripts/main.js). Самостоятельная статическая страница передаёт `interactive={false}` в BaseLayout, если ей не нужны меню и анкета лендинга.

## 5. Где менять конкретный блок

Папки ниже находятся в `src/components/sections/`. В каждой основной файл называется `<Название>Section.astro`, стили — по имени секции, повторяемые данные — `content.js`. Для интерактивных секций рядом есть `client.js`.

| Блок                | Папка                             |
| ------------------- | --------------------------------- |

| Выручка по годам    | `revenue/`                        |
| История             | `story/`                          |
| Сеть и преимущества | `network/`, `network/advantages/` |
| Три формата кофейни | `formats/`                        |
| Отзывы              | `reviews/`                        |

Короткие одиночные подписи могут оставаться в `.astro`. Найти текст можно поиском редактора по `src/` или командой `rg -n 'часть текста' src`.

## 6. Частые правки

| Задача                              | Файл и действие                                                                                                               |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Изменить показатель формата         | [formats/content.js](../src/components/sections/formats/content.js): нужные `facts → label/value`                             |
| Изменить вопрос FAQ                 | [faq/content.js](../src/components/sections/faq/content.js): `question/answer`; эти же данные используются в JSON-LD          |
| Изменить контакты и реквизиты       | [config/site.js](../src/config/site.js); адрес подвала и JSON-LD берётся из одной записи                                      |
| Изменить цвет, шрифт, общие размеры | [tokens.css](../src/styles/tokens.css); загрузка шрифтов — в `fonts.css` рядом                                                |
| Изменить общую кнопку               | [Button.astro](../src/components/ui/button/Button.astro) и `button.css` рядом                                                 |
| Изменить одну кнопку                | Подпись — в компоненте её секции, размещение — в CSS этой секции                                                              |
| Изменить иконку                     | [Icon.astro](../src/components/ui/icon/Icon.astro)                                                                            |
| Изменить логотип                    | `public/assets/brand/`; его цвет не меняется от CSS-переменной                                                                |
| Заменить картинку                   | `public/assets/images/<секция>/`, путь в `config/assets.js` или данных секции; обновить `ui/image/imageMetadata.json` и `alt` |
| Изменить появление элементов        | [motion.js](../src/scripts/motion.js), `styles/motion.css`; особые движения — в CSS секции                                    |

Кнопка с `href` выводится как ссылка; без него — как кнопка. Атрибут `data-open-application` открывает анкету.

**CSS-каскад сохраняется явно:** `global.css` подключает основы, `landing.css` — затем стили секций. Общие параметры меняйте в токенах, правила блока — в его CSS. Порядок импортов влияет на результат. Пошаговые примеры — в [EDITING.md](EDITING.md).

## 7. Анкета

В `components/application/` находятся:

- `steps/` — разметка шагов «О вас», «Проект», «План», «Контакт»;
- `content.js` — подписи, варианты ответов и состав обзора;
- `model.js` — чтение полей, валидация и исключение пустых ответов;
- `controller.js` — открытие, переходы, ошибки, фокус и блокировка фона;
- `fields/`, `progress/`, `review/`, `actions/`, `success/` — части интерфейса;
- `application.css` — оболочка, стабильный размер и внутренняя прокрутка.

Ответы сохраняются при переходах между шагами и сбрасываются при новом открытии. Для нового поля нужны уникальный `name`, запись в `fieldNames`, при необходимости правило `validateStep()` и запись в `reviewDefinitions`.

**Отправка пока локальная.** Экран результата не означает доставку заявки компании. Для Telegram нужен серверный обработчик из старого сайта: его URL, поля и ответы проверяются перед подключением. Секрет бота не помещается в браузерный код.

## 8. SEO и размещение

SEO-настройки — [config/seo.js](../src/config/seo.js), формирование метаданных — BaseLayout и `lib/seo.js`. Подготовлены canonical, Open Graph, JSON-LD, robots, sitemap и 404. Производственный домен по умолчанию — `https://39donuts.ru/`. Другой HTTPS origin задаётся через `SITE_URL` в окружении команды сборки; подпапка этой конфигурацией не предусмотрена.

Dev и preview закрыты от индексации. Техническая подготовка помогает поисковикам читать страницы, но не гарантирует позиции. Подробности — [SEO.md](SEO.md).

На хостинг передаётся содержимое проверенной сборки. Перед загрузкой обязательно прочитайте [DEPLOYMENT.md](DEPLOYMENT.md): там указан фактический состав архива, правила Apache/Nginx и сохранение действующего API компании. Не заменяйте вслепую серверные файлы и настройки.

## 9. Порядок дальнейших изменений

1. Найдите владельца блока и измените его исходники.
2. Для нового блока добавьте папку секции, импорт в LandingPage, CSS в `landing.css`, при необходимости инициализацию в `main.js` и ссылку меню.
3. Выполните `npm run format`, `npm run check`, `npm run check:preview`.
4. Проверьте переносы и поведение на узком и широком экране, клавиатуру и reduced motion. После изменения визуала сравните с утверждённой версией.
5. Для выпуска используйте `npm run release` и инструкцию размещения.

При изменении согласованного состава блоков обновите ожидания `scripts/verify-static-build.mjs`. Наличие `tsconfig.json` обслуживает инструменты Astro; логика проекта написана на JavaScript.

Если правки не видны, проверьте каталог, порт и повторную сборку. Подробный список проверок — [TESTING.md](TESTING.md), результаты аудита — [AUDIT.md](AUDIT.md).
