# Проверки проекта

Проверки делятся на исходники, готовую сборку и браузерные сценарии. Успешная команда сборки не доказывает совпадение визуала, отправку заявки или настройки официального хостинга.

## Команды

```sh
nvm use
npm ci
npm run format
npm run check
npm run check:preview
```

`npm run check` последовательно выполняет:

1. Prettier для кода, конфигурации, README и документации.
2. ESLint для JavaScript.
3. Node-тесты.
4. Production-сборку в `dist/`.
5. Проверку HTML, ресурсов, ID и ARIA.
6. Проверку production SEO.
7. Проверку локальных Markdown-ссылок документации.

`check:preview` собирает `dist-preview/` и проверяет её режим `noindex`, отсутствие production-sitemap и прочие SEO-условия. `npm audit --audit-level=moderate` отдельно проверяет известные уязвимости зависимостей и требует доступ к npm-реестру. Эти действия не устанавливают обновления автоматически.

## Что проверяют тесты

| Файл в `tests/`                 | Контракт                                                                                            |
| ------------------------------- | --------------------------------------------------------------------------------------------------- |
| `application.test.js`           | Обязательность и возраст, заполненные ответы, исключение пустых полей и контакта из обзора          |
| `seo.test.js`                   | Безопасные URL, сериализация JSON-LD, sitemap и соответствие разметки FAQ                           |
| `structure.test.js`             | Относительные импорты, отсутствие циклов, граница маршрутов, независимость основной страницы от 3D  |
| `three-d-renderer.test.js`      | Видимость стекла, сохранение флагов теней, восстановление после ошибки и освобождение AO            |
| `three-d-static-meshes.test.js` | Вершины, UV, нормали, треугольники, исключения объединения, корни анимаций и освобождение геометрии |
| `three-d-textures.test.js`      | Передача текстур частями, отмена и отдельный путь для недогруженных изображений                     |

Тесты структуры читают буквальные относительные импорты текущего проекта. В проекте нет динамически вычисляемых путей импорта или aliases; при их добавлении эту проверку нужно расширить. Сборщик остаётся окончательным проверяющим импортов.

## После изменения интерфейса

Минимум для сверки: 320, 390, 768 и 1440 px, а для граничных правил — ширины рядом с изменённым media query. Движок WebKit и сенсорная эмуляция полезны дополнительно, но не заменяют физический телефон.

Проверьте:

- появление картинок, переносы текста, отсутствие горизонтального переполнения;
- мобильное меню, Escape, возврат фокуса и переход к секции;
- открытие/закрытие анкеты без смещения фона;
- четыре шага, доступные кнопки, внутренний скролл, ошибки, возврат к посещённому шагу и сохранённые ответы;
- обзор всех заполненных полей, исключение пустых полей, отсутствие повтора контакта;
- все форматы мышью/касанием и с клавиатуры Home/End/стрелками;
- переключение категорий FAQ и открытие ответов;
- reduced motion;
- доступность последнего элемента подвала и работу основного scrollbar на десктопе.

Один и тот же сценарий сравнивается до и после правки. Снимок одной новой версии не доказывает, что утверждённый результат сохранился.

## После изменения 3D

Сравните все три модели, подписи и ракурсы; переключение должно синхронно менять HTML и модель. Дополнительно проверьте:

- отсутствие запросов тяжёлых 3D-ресурсов на первом экране;
- выбор другой вкладки во время подготовки;
- выключение, повторное включение и отмену подготовки;
- отсутствие постоянной отрисовки после завершения анимации;
- паузу вне блока и при открытой анкете;
- WebGL недоступен / контекст потерян → фотография;
- размер холста и подпись на узком экране;
- неизменность деталей, цветов, текстур и ракурсов.

Профиль CPU/GPU и загрузку сравнивайте в одинаковых условиях: один браузер/viewport/DPR, отдельные холодные и прогретые сценарии, несколько чередующихся запусков. Число draw calls не равно FPS; счётчик треугольников проходов рендера не равен числу треугольников модели.

## Готовая сборка

[verify-static-build.mjs](../scripts/verify-static-build.mjs) проверяет наличие коммерчески значимого HTML, уникальность ID, цели ARIA, локальные ресурсы и старые переходы. [verify-seo-build.mjs](../scripts/verify-seo-build.mjs) проверяет метаданные, JSON-LD, robots, sitemap, политику, 404 и изображение для ссылок.

[verify-docs.mjs](../scripts/verify-docs.mjs) проверяет относительные ссылки в README и `docs/`: файлы и папки должны существовать. Внешние сайты, текст документации и якоря заголовков этой командой не проверяются.

## CI

[GitHub Actions](../.github/workflows/source-check.yml) запускает проверки на push, pull request и вручную. Версия Node берётся из `.nvmrc`; установка выполняется `npm ci`. Затем выполняются `npm audit`, `check` и `check:preview`.

Workflow не публикует сайт и не изменяет DNS/хостинг. Изменённый локально workflow будет исполняться GitHub только после соответствующей публикации исходников; локальный аудит сам этого не делает.
